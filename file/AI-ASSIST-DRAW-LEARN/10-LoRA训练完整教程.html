10 · LoRA 训练完整教程（AutoDL 实操 · 每一步知其所以然）

前置：已按 06-风格路线-LoRA 确定训练"老师风格"LoRA。底模：NoobAI-XL v1.1。 本教程的每一条命令、每一个参数都有"为什么"。所有 AutoDL 政策均来自官方文档本会话实测抓取；kohya 命令来自其官方文档。

为什么训练发生在服务器而不是你的 4060：SDXL 训练需要约 10GB 显存（fused backward pass + bf16）或 24GB（不 fused，实测来源：2026 训练指南 sanj.dev）；你的 8G 卡放不下。AutoDL 按量计费按秒算，训练 1~2 小时成本 ≈ 一杯奶茶——用钱买显存，比买显卡划算。

1. 阶段一：数据准备（决定成败的一步，全在本地做）

1.1 选图：20~60 张，质量 > 数量

  • 为什么 20~60 张：风格 LoRA 是学"风格的统计分布"。太少（<10）学不到稳定的风格；太多（>100）风格混杂、训练时间和过拟合风险同步上升。社区基准：20~60（sanj 指南）。
  • 为什么质量 > 数量：模糊、崩坏、跨风格的图会往分布里注入噪声——数据质量决定模型上限，超参数只决定你离上限多近（这是可迁移到一切训练的第一原则）。
  • 为什么裁掉水印/签名：模型会把水印学成风格的一部分，生成时到处长水印。
  • 风格一致性优先：同一时期、同一画风的作品优先；跨风格大跳跃的剔除。

1.2 预处理

  • 统一到 1024 附近即可，不需要统一长宽比——训练时 enable_bucket 会把不同比例的图分桶处理（见 §3.1），暴力缩放裁剪反而损伤画面。
  • 文件名无要求（任意排序），但建议 001.png 这种零填充命名，配合打标文件好对应。

1.3 打标（为什么的为什么）

每张图一个同名 .txt，内容是逗号分隔的标签。用 WD14 Tagger v3（你 ComfyUI 里已有同族工具，或用 kohya 自带的 tag_images_by_wd14_tagger.py）。

001.png  →  001.txt 内容：
style_t_xxx, 1girl, long hair, white dress, looking at viewer, masterpiece
1
2

三个为什么：

  1. 为什么要有统一的触发词（style_t_xxx）：LoRA 学到的本质是"触发词 → 风格分布"的绑定。触发词必须：统一（每张图都有）、独特（不和模型已有词冲突，所以用自定义前缀）、放在最前（keep_tokens 保护它）。
  2. 为什么必须保留内容标签：如果不写"1girl, long hair"，模型会把风格和"你选的这批图的题材"绑死——你画一个机器人它也给你画成长发少女。内容标签让风格和内容解耦。
  3. 为什么不用画师真名当触发词：① 模型（NoobAI 用完整 Danbooru 训练）可能内置了该画师标签，两者打架；② 伦理（见 06 §6）。

2. 阶段二：租服务器 + 无卡模式配置环境

2.1 租卡

  • 选 24GB 显存及以上的按量计费实例（如 4090；你看到的 RTX PRO 6000 96GB 也完全没问题——SDXL 训练 24G 已绰绰有余，更大的卡只是更宽裕）。
  • 为什么 24G：SDXL 训练不 fused 需要 ~24GB（sanj 指南实测）。24G 卡不需要 --fused_backward_pass（而且该参数目前只支持 Adafactor 优化器，kohya 官方文档确认）。
  • 先充 20~50 元足够（训练几块钱 + 数据盘/存储几分钱）。

2.2 无卡模式开机（配置环境，不花 GPU 钱）

  1. 控制台租用实例时选择无卡模式开机（选项位置以控制台实际为准）。
  2. 通过 JupyterLab 或 SSH 登录。
  3. 全部环境配置在无卡模式下完成（见 2.3），然后关机。
  4. 之后再以GPU 模式开机训练（§3）。

为什么能这样：配置环境（装 python 包、下载模型）不需要 GPU 算力；无卡模式不占用 GPU、不计 GPU 费，只按存储计费（官方计费文档明确提到无卡模式是"关机后 GPU 不预留"时的解决手段之一）。⚠️ 无卡模式下 CPU 弱，大文件 Hash 计算会慢（官方网盘文档原话），传大文件建议放 GPU 模式或耐心等待。

3. 阶段三：GPU 模式训练

3.1 数据集配置 train/dataset_config.toml（每个键的为什么）

toml
[general]
shuffle_caption = false     # 为什么 false：标签顺序对 CLIP 有影响；风格 LoRA 保持稳定顺序（触发词在前）
caption_extension = ".txt"  # 打标文件的扩展名
keep_tokens = 1             # 前 N 个 token 永不参与打乱——保护最前面的触发词

[[datasets]]
resolution = 1024           # SDXL 原生分辨率（NoobAI 官方推荐面积 ~1024²，见 03 §3）

min_bucket_reso = 512
max_bucket_reso = 2048

参数值为什么
--network_dim / --network_alpha32 / 16LoRA 的容量（rank）与强度（alpha/dim 比值）。32/16 是 kohya 官方示例与风格 LoRA 社区基准；想要风格更强可以 64/32，但过拟合风险同步上升。容量-速度-稳定三角
--learning_rate1e-4总学习率。太大→发散，太小→学不动。官方示例即 1e-4
--unet_lr / --text_encoder_lr1/21e-4 / 1e-5 / 1e-5为什么文本编码器学习率低 10 倍：风格主要靠 UNet 学；文本编码器是"共用器官"，动太多会伤模型原有能力。SDXL 有两个文本编码器所以是 lr1/lr2
--optimizer_type="AdamW8bit"—8bit 版 AdamW，省显存，训练稳定（kohya 官方示例）
--lr_scheduler="constant"—官方示例用 constant（全程同一学习率，简单稳定）。社区也常用 cosine_with_restarts（尾段更精细收敛）——先按官方示例跑通，想精细再换
--max_train_epochs=15—训练轮数。步数公式：步数 = 图数 × num_repeats × epochs ÷ batch_size。40 图 × 5 × 15 ÷ 1 = 3000 步（社区推荐 1000~3000 的上界）；想少点就 repeats=3 → 1800
--save_every_n_epochs=1—为什么每 epoch 存一份：用于过拟合对比（§4）——你不需要猜第几个 epoch 最好，直接扫
--mixed_precision="bf16"—40 系卡原生支持 bf16，快且稳（kohya 官方推荐）
--gradient_checkpointing—省显存换速度（官方示例默认开，说明官方按通用配置给的）
--cache_text_encoder_outputs --cache_latents—为什么能缓存：训练中每张图的文本/图像编码结果在训练期间不变，提前编码存盘，每个 epoch 直接复用——显著提速降显存（kohya 官方推荐）
--seed=42—训练可复现

3.3 训练中的观察（为什么不用慌）

  • loss 曲线不会平滑下降——抖动是正常的，整体趋势下降即可。这是你 2025-12-03《某轮次的退步是正常的》原文的机制，训练神经网络时它字面成立。
  • 训练结束（15 个 epoch ≈ 1~2 小时，看卡型）→ 立刻关机（按秒计费）。

4.2 本地验证（过拟合判定，固定种子）

  1. 放 ComfyUI\models\loras\style_teacher.safetensors
  2. 工作流（03 文档的 W1 节点链）加 LoraLoader 节点，串在 Checkpoint 与 KSampler 之间
  3. 固定种子，只扫 weight：0.4 / 0.7 / 1.0 各出一张（可用 WD14 从老师作品提标签做提示词）
  4. 判定（06 §5 详表）：1.0 时风格强但细节僵死/糊 = 过拟合 → 用早期 epoch 的存档（这就是每 epoch 保存的意义）；0.7 自然、1.0 崩 = 训练过头，下次减 epochs；1.0 风格仍弱 = 欠拟合，加 epochs 或加数据。

5. 举一反三（这套流程能推广到什么）

5.0 LoRA 类型学（先看这个，再谈变体）

类型不是由训练方法决定的，是由"数据和触发词定义的不变项"决定的——三种 LoRA 的训练流程（§1~§4）完全通用。

类型不变项可变项学到什么触发词数据选择内容标签策略
画师/风格 LoRA画法内容全变"怎么画"自定义标签风格统一、内容多样（否则风格绑死题材/角色）保留内容标签，让风格与内容解耦
角色 LoRA角色身份角度/表情/场景"是谁"角色名同一角色、角度/表情/场景多样强调角色特征标签（发型/瞳色/服装）
概念 LoRA事物类别/个体形态/环境"是什么"概念标签同一事物不同形态保留类别标签

判定口诀：拿到一批图，问自己——我要的是"内容里的那个东西"还是"处理这批内容的方式"？想要方式 → 风格 LoRA；想要那个东西 → 角色/概念 LoRA。

组合玩法（LoRA 的心智模型的延伸）：角色 LoRA + 风格 LoRA 叠加 = "以某画师的画风画某个角色"——ComfyUI 里两个 LoraLoader 串联、权重各自调。这是将来原创 CP 素材库、漫画角色一致性的核心工具。

变体对照表

变体改动点不变的部分
角色 LoRA触发词=角色名；数据=同一角色多角度/多表情/多服装（一致性优先）；dim 可升 64 抓脸部细节数据准备→无卡配环境→GPU 训练→回收验证 全流程同构
概念 LoRA（物体/服装/场景）触发词=概念名；选图=该概念不同形态同上
FLUX LoRAkohya 换 flux_train_network.py（官方文档 docs/flux_train_network.md 存在）；显存 16~24G（sanj 实测）TOML 数据集配置、加速流程、验证方法完全同构
换云平台（阿里云/腾讯云/恒源云）控制台细节不同"无卡配环境→GPU 训练→产物回收"的心智模型通用

可迁移的四个原则（训练领域的元知识）：

  1. 数据质量决定上限——选图与打标花的时间永远值得
  2. 容量-速度-稳定三角——dim、batch、epochs 不是越大越好，先按基准跑通再调
  3. 验证永远在训练环境之外——固定种子、独立工具（ComfyUI）、独立判定标准
  4. 一切皆数据流，可缓存可复现——cache_latents、seed、每 epoch 存档：把训练当作可重现的流水线而非玄学
